# План пакетных откликов

## Цель

Дать агенту возможность отправить явно подтверждённый пакет откликов до
заданного пользователем количества. Ошибка одной вакансии не должна останавливать
остальные отклики. Все пропущенные, неопределённые и неиспользованные вакансии
должны быть перечислены в итоговом отчёте.

## Этапы

1. **Пакетная модель и лимиты — реализовано.** Один пакет содержит общее резюме,
   целевое количество откликов и упорядоченный список кандидатов с запасными.
   Лимиты: до 20 целевых откликов и до 50 кандидатов.
2. **Безопасная подготовка — реализовано.** Сервер получает точные данные
   вакансий, исключает дубликаты, ошибки чтения, явно отмеченные агентом вакансии
   и описания с очевидными признаками prompt injection. Подготовка ничего не
   отправляет.
3. **Одноразовое подтверждение — реализовано.** Весь список кандидатов, резюме,
   письма, порядок и лимит связаны с короткоживущим одноразовым токеном.
4. **Изолированное выполнение — реализовано.** Отклики идут последовательно;
   обычная ошибка или отказ пропускает одну вакансию и не останавливает пакет.
   Неоднозначный результат занимает один слот лимита, поскольку POST мог пройти.
5. **Итоговый отчёт — реализовано.** Результат разделён на `submitted`,
   `skipped`, `unknown` и `not_attempted`.
6. **Интеграция и проверка — реализовано.** Инструкция агента и README
   обновлены; MCP публикует оба пакетных инструмента, локальные тесты и линтер
   проходят.

## Граница безопасности

- Пакет не отправляется одним неподтверждённым вызовом.
- Пользователь видит все подготовленные вакансии и точные письма до отправки.
- `HH_ENABLE_APPLICATIONS=true` по-прежнему обязателен.
- Токен подтверждения одноразовый и истекает через 10 минут.
- Содержимое вакансии не может увеличить лимит, заменить резюме или письмо.
- Автоматического повтора неоднозначного POST нет.
